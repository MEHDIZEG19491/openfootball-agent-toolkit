# OpenFootball Agent Toolkit

**A private, self-hosted workspace for football representation and recruitment.**

Manage player and coach records, club needs, negotiations and mandates. Compare
players with recorded requirements and see **why each condition passes, fails or
needs more data**. Keep your organization's records on your own machine or server.

For football agents, clubs, sporting directors, scouts and coach representatives
who currently coordinate this work across spreadsheets, notes and messages.

**Status:** v0.1.0 MVP, available as public source for evaluation. Not yet a mature
production service. No public adoption or performance claims. See the
[validation report](docs/QUALITY-AUDIT.md) for executed checks and remaining gates.

## What works

- Players: positions, dual nationality, date of birth, contract status, monthly
  salary expectations, expected transfer fee, documented caps and resource links.
- Coaches: licences, systems, experience, languages, availability and regions.
- Clubs and opportunities with age, position, nationality, salary, transfer budget,
  availability, appearance windows and deadlines.
- Explainable deterministic matching with **MATCH / NO MATCH / INCOMPLETE**.
- Twelve recruitment stages, linked to players and opportunities.
- Mandate records, exclusivity and start/end dates; dashboard alerts for active
  mandates expiring within 30 days. These records do not create legal authority.
- Community rule-pack schema, source metadata, verification states and validity
  dates. Only fictional, clearly unverified examples are bundled.
- English, French and Arabic UI, including right-to-left layout.
- One-time owner setup, password authentication and Owner / Editor / Viewer roles.
- CSV and JSON imports with preview, atomic commit and preserved identifiers;
  exports for owners and editors. Viewers can read records but cannot bulk-export.
- SQLite persistence, migrations, audit events, optimistic edit conflict detection,
  an online backup script and Docker configuration.

Not included in v0.1: file uploads, email reminders, legal contract templates,
coach matching, multi-tenant hosting, PostgreSQL, SSO, external integrations,
exchange rates, AI recommendations, website scraping or automatic regulation updates.

## Quick start — Node.js 24

Download the source ZIP with GitHub's **Code → Download ZIP**, or clone the repository:

```sh
git clone https://github.com/MEHDIZEG19491/openfootball-agent-toolkit.git
cd openfootball-agent-toolkit
npm ci --ignore-scripts
npm run setup
npm run build
npm start
```

Open **http://localhost:3000/setup**. Copy `BOOTSTRAP_TOKEN` from your local `.env`
file and create your owner account with a password of at least 12 characters.
Then sign in at **http://localhost:3000/login**. Setup closes after the first owner
is created. Remove `BOOTSTRAP_TOKEN` from the environment after setup and restart.
Keep `.env` private. There is no default account or shared password.

Use `localhost` consistently: a form opened on `127.0.0.1` will be rejected when
`APP_ORIGIN` is `http://localhost:3000`. This is the request origin protection.

On the empty dashboard, **Load fictional examples** is an optional owner action.
For a clean real workspace, start with a different database path, not the demo
installation. Add colleagues in Settings; each installation is one organization.

Development: `npm run dev` after setup. Node 24 includes the SQLite driver; no
separate database server, Python build tools or ORM generation step is needed.

## Docker

With Node installed, run `npm run setup` to create a random token, then:

```sh
docker compose up --build -d
```

Alternatively copy `.env.example` to `.env`, replace the placeholder token with
at least 32 random characters generated by a password manager, and run Compose.
Visit the same setup URL. The default port is published **only on loopback**.
The container runs as a non-root user; data and backups use named volumes.
Never use `docker compose down --volumes` on an installation whose data you need.

Docker is configured and has a CI smoke job, but could not be executed in the
build workspace because no Docker engine was available. Run that job before
relying on the image. Self-hosting with HTTPS: [deployment guide](docs/DEPLOYMENT.md).

## Configuration

| Variable                  | Default / behavior                                                          |
| ------------------------- | --------------------------------------------------------------------------- |
| `APP_ORIGIN`              | `http://localhost:3000`; exact browser origin. HTTPS required off loopback. |
| `DATABASE_PATH`           | `./data/openfootball.sqlite`; runtime resolves it to an absolute path.      |
| `BOOTSTRAP_TOKEN`         | Random secret generated by setup; required only for first owner creation.   |
| `COOKIE_SECURE`           | `false` locally; HTTPS always enables secure session cookies.               |
| `NEXT_TELEMETRY_DISABLED` | `1`; no analytics or outbound application telemetry.                        |
| `HOSTNAME_BIND`           | `127.0.0.1` for `npm start`; set deliberately for self-hosting.             |
| `PORT`                    | `3000`; changing it also requires updating `APP_ORIGIN`.                    |

Resource links are stored as links and are never fetched by the server. Opening
an external link uses that provider's access controls. Store private resources in
an access-controlled system, not a public URL. Database files are not encrypted
by this app; use disk encryption and protected backups.

## A practical workflow

1. Create clubs, players and coaches. Leave unknown facts empty.
2. Create a club opportunity; specify currency, date window and eligible cap levels.
3. Open Matching and review each criterion. A high score never cancels a failure.
4. Add a player to the recruitment pipeline, then update the stage as work proceeds.
5. Record mandate dates and review the dashboard for upcoming expiries.
6. Export collections or make a database backup before migrations or major imports.

## Architecture and development

Next.js App Router, TypeScript, React and Tailwind/CSS; Node's built-in SQLite.
Pure domain functions in `src/core`, data/auth/import services in `src/server`,
server pages and JSON endpoints in `src/app`, reusable localized UI in `src/ui`.
See [ARCHITECTURE.md](ARCHITECTURE.md) for boundaries, trade-offs and migration strategy.

```sh
npm run lint
npm run typecheck
npm test
npm run test:coverage
npm run build
npm run test:integration
npm run format:check
npm run audit:dependencies
```

The integration suite starts the compiled production server using an isolated,
disposable database and checks actual HTTP requests. It does not operate on your
installation. Browser and assistive-technology tests are a separate release gate.

```sh
npm run backup
```

Backups contain private data and password hashes. They are saved under the ignored
`private/backups` directory unless you supply another destination. See
[backup and restore](docs/DEPLOYMENT.md#backups-and-restore).
