# Legitimate adoption plan

The repository must be valuable without a grant or subscription benefit. There
are currently no verified public users, download counts, contributors, testimonials
or adopting organizations in the project record. The following is a proposal.

## First month after a reviewed public release

**Week 1: installation pilots.** Personally invite a small, willing group of agents,
scouts and sporting directors already in your professional network. Ask them to
install locally using fictional data before any sensitive records. Observe setup,
one player/opportunity match and one import. Record consent, actual completion,
problems and suggestions privately; publish only anonymized findings with permission.
Five willing pilot testers is an outreach goal, not an existing user count.

**Week 2: workflow feedback.** Ask which steps replace real spreadsheet/message
work, where “unknown” is confusing, what makes salary/cap evidence reliable, and
which privacy controls are missing. Include coach representatives, not only player
agents. Prioritize verified failures over extra features. Fix and release small,
reviewable patches; do not manufacture commits for activity charts.

**Week 3: developer contributions.** Publish a concise technical walkthrough on
GitHub and, if welcome under the community's rules, football analytics and OSS
forums. Point developers to one bounded issue with a reproducible fixture. Thank
actual contributors after work is accepted. Translation, accessibility and
installation reports are meaningful contributions too.

**Week 4: public lessons.** On LinkedIn, explain the workflow solved, show real
fictional-data screenshots and link to the actual repository and release. Share
what is unfinished and what testers observed. Avoid tagging unrelated people or
posting in groups without permission. No messages are automatically sent by this plan.

for player and coach records, club opportunities and explainable recruitment matching.
It supports English, French and Arabic and keeps installation data private by default.

and contributions in testing, accessibility, translations and documented rule formats.
Repository and setup: [INSERT ACTUAL PUBLIC URL].

Do not claim it is adopted by clubs merely because they received an invitation.
Screenshots must show fictional or properly consented data. State affiliation and
AI assistance honestly. Never buy stars, fake accounts, downloads, PRs or endorsements.

## Measure with consent and defined denominators

Keep a private evidence log: date, release/commit, data source, metric definition,
count, period and caveat. GitHub stars/forks are interest, not active users. Release
asset downloads include repeat downloads and automation. Contributors should be
counted from accepted substantive work, separating bots. A survey response is not
an authenticated install. Locally hosted installations have no telemetry; activity
must be voluntarily reported and cannot be inferred from repository traffic.

Define active pilot usage before counting it, e.g. a consenting organization that
reports completing a real workflow during the last 30 days. Publish an aggregate
only when disclosure cannot identify private participants. Retain permission for
any named organization/logo/testimonial. Mark unmeasured metrics “unknown.”

Re-evaluate product direction after actual pilot findings. Review readiness for
support programs only after verifiable use, releases and maintainership exist;
there is no entitlement or guaranteed selection.
